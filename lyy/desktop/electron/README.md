# Growth Garden Desktop (Windows)

This directory is the Electron shell for the Windows desktop build. It starts
the Spring Boot jar with the `desktop` profile, waits for the local server, and
then opens the app window.

## Development

Build the jar first:

```powershell
cd D:\code\her\lyy\lyy
.\mvnw.cmd -DskipTests package
```

Then install Electron dependencies and start:

```powershell
cd desktop\electron
npm install
npm start
```

Set `JAVA_HOME` if `java` is not on PATH.

If the Electron binary download is slow or fails in mainland China:

```powershell
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
npm install
```

The desktop backend stores its data under
`%APPDATA%\GrowthGarden\.growth-garden` because the Electron process passes
`-Duser.home=<Electron userData>` to Java.

The desktop account page includes a DeepSeek Key setting. The key is written to
the local config directory and applied immediately. No separate administrator
login is needed for this setting.

## Hidden letters

The private letter seed stays in `db/export/seed-letters.sql` and is converted
to `src/main/resources/db/desktop/letters.sql` by:

```powershell
.\desktop\prepare-letters.ps1
```

The generated file is ignored by git. `build-runtime.ps1` runs this step before
packaging, so local desktop builds include the letters.

For GitHub Actions, add the contents of `db/export/seed-letters.sql` as a
repository secret named `LETTERS_SEED_SQL`. The release workflow fails if this
secret is missing, so a release cannot silently ship without the letters.

## Packaging

Build a small JRE:

```powershell
cd D:\code\her\lyy\lyy
.\desktop\build-runtime.ps1
```

Build the NSIS installer:

```powershell
cd desktop\electron
npm install
npm run dist
```

Output is in `desktop/electron/dist`.

## Updates

The shell checks GitHub Releases only in a packaged build. Releases need a
`latest.yml` file generated by electron-builder. Set `GH_TOKEN` and publish with:

```powershell
npx electron-builder --win nsis --publish always
```

For private repositories, do not embed a token in the app. Publish installers to
a public release repository or use a server-side update endpoint.

The repository root also contains `.github/workflows/desktop-release.yml`. Push a
version tag to build and publish:

```powershell
git tag v1.0.0
git push origin v1.0.0
```

Add the private letter SQL as the `LETTERS_SEED_SQL` repository secret. The tag
version is applied to `package.json` during the workflow, so the tag and
`latest.yml` stay in sync.
